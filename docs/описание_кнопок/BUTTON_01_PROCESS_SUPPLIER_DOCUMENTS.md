# 📥 КНОПКА 1: Обработка Бланков поставщика

**Положение в меню:** Подменю "🧾 Заказ" (первое подменю MENU_CONFIGS primary_menu)
**Статус:** ✅ Главная кнопка цикла обработки документов от поставщика
**API:** `POST /api/v1/price/process/{project}`
**Документ в GAS:** `/gas/02Обработка бл.зак Mt.js` (образец для MT)
**Ярлыки меню:** "📥 Обработка Б/З поставщика" (заменяет 3 старые кнопки)

---

## 📝 Описание

Обработка Бланков поставщика - это **главная кнопка** для загрузки и интеграции прайс-листов от производителя. При нажатии на кнопку система **автоматически выполняет все три режима обработки последовательно**:

1. **Обработка Б/З поставщик (MAIN)** - основные товары
2. **Обработка Тестер (TESTER)** - дополнительно тестовые образцы
3. **Обработка Пробники (SAMPLES)** - образцы для испытания

Функция берет прайс от производителя, парсит его, синхронизирует артикулы, распределяет ID-P коды, копирует данные на все рабочие листы и пересчитывает формулы.

---

## 📊 Структура проекта MT (на примере)

### Положение кнопки в меню

```
🧾 Заказ (подменю MENU_CONFIGS primary_menu)
├─ 📥 Обработка Б/З поставщика ⭐ (новая объединенная кнопка)
│  └─ Выполняет: MAIN → TESTER → SAMPLES (последовательно)
└─ 📊 Загрузить остатки
```

### Основной лист
- **"Главная"** - где хранятся все артикулы, их данные, ID-P коды

### Рабочие листы (синхронизируются с "Главная")
- **"Заказ"** - для оформления заказов
- **"Динамика цены"** - история изменения цен, расчет закупочной цены
- **"Расчет цены"** - расчетные формулы (К-т, РРЦ и т.д.)
- **"ABC-Анализ"** - анализ товаров по объему
- **"Сертификация"** - сертификационные данные
- **"Этикетки"** - данные для печати этикеток

### Источники данных (листы с прайс-листами)
- **"-Б/З поставщик"** - основной прайс (режим MAIN)
- **"-Тестер"** - тестовые образцы (режим TESTER)
- **"-Пробники"** - пробные партии (режим SAMPLES)

### ✅ Шаг 6: Синхронизировать ID артикулов с "Главной" ⚠️ КРИТИЧЕСКИЙ

```
Функция: _syncIdWithMain(processedRows, headers, articles, groups)
Вход: обработанные данные из Шага 2
Выход: SyncResult {
  assignedIdp: {article: id},
  createdRows: [...],
  updatedRows: [...],
  groupChanges: [...],
  barcodeMismatches: [...]
}
```

**Действия:**
- Получить текущие артикулы из листа "Главная"
- **ДЛЯ КАЖДОГО артикула из прайса:**
  - ❌ Если артикула НЕ существует:
    - Добавить новую строку в конец листа "Главная"
    - Заполнить: Артикул, Название, Объем, BAR CODE, Цена, Группа
    - Присвоить новый ID-P (максимум + 1)
    - Добавить в createdRows
  - ✅ Если артикул существует:
    - Обновить данные (если отличаются)
    - Проверить что BAR CODE совпадает
      - Если не совпадает → добавить в barcodeMismatches
    - Использовать существующий ID-P
    - Добавить в updatedRows
- Применить Smart Match для новых артикулов

**Логирование:**
