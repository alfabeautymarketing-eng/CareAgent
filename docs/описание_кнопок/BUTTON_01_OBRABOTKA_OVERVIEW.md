# Кнопка 1: Обработка (Обработка Б/З поставщика)

**Функция сервера:** `serverProcessPrimaryData` -> `callServerProcessPrice("{project}", "all")`
**API:** `POST /api/v1/price/process/{project}`
**Исполнитель логики:** `src/services/price_processor.py` (Class `PriceProcessor`)
**Конфигурации:** `config/projects/mt.yaml`, `sk.yaml`, `ss.yaml`

---

## Описание

Кнопка "Обработка" — **главная кнопка** для загрузки и интеграции прайс-листов от производителя. При нажатии система автоматически выполняет **все циклы обработки последовательно** (количество зависит от проекта).

Функция берёт прайс от производителя, парсит его, синхронизирует артикулы с листом "Главная", распределяет ID-P коды, копирует данные на все рабочие листы и пересчитывает формулы.

**У каждого проекта свои особенности:**
- Разное количество циклов обработки
- Разные исходные листы и структура прайса
- Разные методы определения групп товаров
- Разные дополнительные шаги (скидки, очистка колонок)

## Общий алгоритм (15 шагов)

Для каждого цикла обработки выполняются следующие шаги:

1. **Чтение исходных данных** — из листа в документе поставщика
2. **Парсинг** — конвертация в структурированный формат (ParsedRow)
3. **Создание снэпшота** — структурированная копия (ID-P, Арт., Название, Цена, Группа)
4. **Очистка колонок** (только main) — ID-P, ЦЕНА EXW, ID-G (+ID-L для SK)
5. **Синхронизация с "Главная"** — сравнение артикулов, Smart Match для новых
6. **Заполнение ID-G** — для строк без ID-P
7. **Заполнение ID-P на всех листах** — по данным из "Главная"
8. **Копирование цен** — на "Динамика цены" и "Расчет цены"
9. **Скидка** (только SK) — 20% на "Динамика цены"
10. **Формулы "Динамика цены"** — EXW ALFASPA, Закупочная, DDP-МОСКВА
11. **Формулы "Расчет цены"** — INDEX/MATCH из "Динамика цены"
12. **Расчётные формулы** — К-т, РРЦ, Опт
13. **Репликация новых артикулов** — на листы Сертификация, Этикетки, Заказ и др.
14. **Обновление статусов** — для последнего цикла каждого проекта

## Снэпшот (структурированные данные)

После парсинга создаётся снэпшот-лист в исходном документе поставщика с именем `"{лист} {дд.мм.гг}"` (напр. `-Б/З поставщик 04.02.26`).

Снэпшот содержит **структурированные данные** (не raw-копию):

| ID-P | Арт. произв. | Название ENG | Объём | шт./уп. | ЦЕНА EXW | Группа |
|------|-------------|-------------|-------|---------|----------|--------|

Эти данные используются для сверки и загрузки в базу данных.

## API endpoint

```
POST /api/v1/price/process/{project}

Body:
{
  "mode": "all",                    // "all" для полной обработки
  "spreadsheet_id": "1a2b3c...",    // ID целевой таблицы (опционально, берётся из конфига)
  "source_doc_id": "1x2y3z...",     // ID документа поставщика (опционально)
  "dry_run": false                  // true для превью без записи
}
```

### Ответ при успехе
```json
{
  "status": "success",
  "message": "Полная обработка SK: 2 циклов, 280 строк",
  "cycles": 2,
  "total_rows": 280,
  "total_new": 15,
  "errors": [],
  "results": [...]
}
```

### Ответ при ошибке
```json
{
  "status": "error",
  "message": "Полная обработка SK: 2 циклов, 245 строк (ошибок: 1)",
  "errors": ["probes: Не удалось прочитать данные из листа '-Пробники'"],
  "results": [...]
}
```

---

## Обработка ошибок

- Ошибка в любом цикле записывается в лист "Логи" + возвращается GAS-клиенту
- GAS показывает toast с деталями ошибки (15 секунд)
- Если все циклы завершились с ошибкой → `status: "error"`
- Если часть циклов успешна → `status: "success"` + массив `errors`
