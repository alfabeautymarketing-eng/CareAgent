## Описание

Кнопка "Обработка" для проекта SS (ООО Сан / Carros) — самая простая из трёх проектов. Отличается:

1. **Один цикл обработки** (только main)
2. **Маркерная логика** — специальные строки в прайсе переключают режим парсинга
3. **Нумерация строк в колонке A** — данные начинаются с колонки B (индекс 1)
4. **Извлечение чисел из "Формы выпуска"** для группы SAMPLES

## Отличие от MT/SK: Маркерная логика парсинга

### Структура исходного файла SS

Прайс SS (Carros) имеет уникальную структуру: **колонка A содержит нумерацию строк**, а данные начинаются с колонки B. Также в прайсе присутствуют **маркерные строки**, которые переключают режим парсинга.

**Индексы колонок:**

| Индекс | Колонка Excel | Содержимое |
|--------|--------------|-----------|
| 0 | A | Нумерация строк (не используется) |
| 1 | B | CODE — Артикул производителя |
| 2 | C | PRODUCT_NAME — Название ENG |
| 3 | D | SIZE — Объём |
| 4 | E | PACK — Форма выпуска |
| 5 | F | BAR_CODE_ACL — Штрихкод |
| 6 | G | QTY_BOX — шт./уп. |
| 7 | H | EX_WORKS_CARROS — Цена EXW |

### Маркеры

**1. "PROFESSIONAL PRODUCTS"**
- Когда парсер встречает эту строку в колонке A (первой ячейке)
- Включается **профессиональный режим**
- Все последующие группы получают суффикс **"-ПРОФ"**
- Пример: группа "Hair Care" становится "Hair Care-ПРОФ"

**2. "PROMOTIONAL MATERIALS"**
- Когда парсер встречает эту строку
- Обработка **полностью прекращается**
- Все строки после этого маркера игнорируются
- Промо-материалы не входят в прайс

### Логика парсинга SS (пошагово)

```
is_professional_mode = false

Для каждой строки после заголовков:

    first_cell = row[0].upper()  <- Первая ячейка (колонка A)

    Если first_cell содержит "PROMOTIONAL MATERIALS":
        -> СТОП. Прекращаем обработку.
        -> break

    Если first_cell содержит "PROFESSIONAL PRODUCTS":
        -> is_professional_mode = true
        -> continue

    code = row[1]       <- Колонка B
    name = row[2]       <- Колонка C

    Если name заполнено AND code пусто:
        -> Это строка группы
        -> current_group = name
        -> Если is_professional_mode:
            -> current_group = name + "-ПРОФ"
        -> continue

    Если code заполнено AND name заполнено:
        -> Это артикул
        -> Парсим SIZE, PACK, BAR_CODE, QTY, PRICE
        -> group = current_group

        -> Если группа == "SAMPLES" AND samples_logic включена:
            -> Извлекаем число из PACK (формы выпуска)
            -> units_per_pack = найденное число
            -> Пример: PACK="Box of 10" -> units=10

        -> Создаём ParsedRow
```

## Отличие от MT/SK: Извлечение чисел для SAMPLES

Для группы "SAMPLES" в SS прайсе, поле "шт./уп." определяется не из колонки QTY_BOX, а **извлекается из колонки PACK** (Форма выпуска) с помощью регулярного выражения `\d+`.

Пример:
- PACK = "Box of 10 units" -> units_per_pack = **10**
- PACK = "Set 5pcs" -> units_per_pack = **5**

Это настраивается в конфиге:
```yaml
samples_logic:
  enabled: true
  group_name: "SAMPLES"
  extract_number_from: "form"      # Из колонки "Форма выпуска"
  extract_number_to: "units_per_pack"  # В поле "шт./уп."
  pattern: "\\d+"                  # Регулярное выражение
```

## Алгоритм работы (пошагово)

Общий алгоритм совпадает с MT (15 шагов), со следующими отличиями:

### Шаг 7 (Чтение данных) — без цветов

SS не использует цвета фона. Читаются только значения:
```
values = ws.get_all_values()
backgrounds = None  <- Не запрашивается для SS
```

### Шаг 8 (Парсинг) — маркерная логика

1. Ищет строку заголовков ("CODE", "PRODUCT", "SIZE" в первых 10 строках)
2. Данные начинаются после заголовков
3. Маркеры "PROFESSIONAL PRODUCTS" и "PROMOTIONAL MATERIALS" управляют парсингом
4. Группа определяется строками без CODE, но с NAME

### Шаг 17 (Статусы) — выполняется всегда

В отличие от MT (только для samples) и SK (только для probes), SS обновляет статусы после **каждой** обработки, т.к. это единственный цикл:
```yaml
processing_cycles:
  - mode: main
    update_statuses_after: true  # Всегда
```

## Обработка ошибок (SS-специфичные)

| Ситуация | Поведение |
|----------|-----------|
| Маркер PROMOTIONAL MATERIALS — обработка остановлена | Штатное поведение, не ошибка |
| Заголовки не найдены | Используется первая строка как заголовки (default=0) |
| SAMPLES без числа в PACK | units_per_pack берётся из колонки QTY_BOX (стандартно) |
| Число в PACK не найдено (regex fail) | units_per_pack = значение из QTY_BOX |

Остальные ошибки обрабатываются аналогично MT (см. BUTTON_01_OBRABOTKA_MT.md).
