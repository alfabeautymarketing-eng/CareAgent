# 🔄 Кнопка: Синхронизировать всё

**Файл:** `BUTTON_SYNC_FULL.md`
**Функция GAS:** `runFullSync`
**Функция сервера:** `POST /api/v1/sync/full`
**Исполнитель логики:** `src/services/sync.py` (метод `sync_full` / `sync_full_async`)
**Расположение в меню:** ⚙️ Настройка > 🔄 Синхронизация

---

## 📝 Описание

Запускает полную синхронизацию всех данных в таблице по всем активным правилам. Проверяет каждую строку на каждом листе-источнике и, при наличии расхождений, обновляет целевые листы. Операция гарантирует, что все связанные данные между листами находятся в согласованном состоянии.

**Ключевые особенности:**
- Работает для всех проектов (MT, SS, SK).
- Поддерживает как однонаправленные (`unidirectional`), так и двунаправленные (`bidirectional`) правила.
- Использует ScriptLock для предотвращения параллельного запуска.
- При большом объеме данных работает пакетно с автоматическим продолжением через триггеры GAS.
- Синхронизирует данные также в Supabase (если настроено).

---

## ⚙️ Алгоритм работы

### Фаза 1: Подтверждение и блокировка (GAS)
1. **Пользователь** нажимает кнопку "🔄 Синхронизировать всё" в меню.
2. **GAS** показывает диалог подтверждения: "Операция проверит и, при необходимости, исправит все несоответствия по активным правилам. Продолжить?"
3. Пользователь подтверждает (YES).
4. **GAS** захватывает `ScriptLock` (таймаут 15 сек). Если блокировка не получена, значит другой процесс уже выполняется.
5. **GAS** сбрасывает прошлое состояние (`STATE_KEY`) и удаляет старые таймеры продолжения.

### Фаза 2: Загрузка правил (Server)
6. **GAS** отправляет запрос на сервер `POST /api/v1/sync/full` с параметрами `{spreadsheet_id, project, source_sheet}`.
7. **Server** загружает правила из файла `config/rules/{spreadsheet_id}.yaml`.
8. **Server** фильтрует правила: оставляет только те, у которых `source_sheet` совпадает с текущим листом (для `unidirectional`) или `sheet_a`/`sheet_b` (для `bidirectional`).

### Фаза 3: Обработка строк (Server)
9. **Server** открывает лист-источник через Google Sheets API и считывает все значения.
10. **Server** строит карту заголовков (`header_map`).
11. **Server** итерируется по каждой строке данных (пропуская заголовок):
    - Берет артикул из колонки A (ключ строки).
    - Для каждого подходящего правила определяет `source_header`.
    - Находит значение в исходной ячейке.
    - Вызывает `_apply_rule_extended()` для записи значения в целевой лист/ячейку.
12. При ошибке в отдельной строке/правиле ошибка логируется, но обработка продолжается.

### Фаза 4: Результат
13. **Server** возвращает статистику: `{status, rows_processed, errors}`.
14. **GAS** показывает toast с результатом синхронизации.
15. Записи о синхронизации сохраняются в журнал синхронизации (`SyncLogService`).

## ⚠️ Важные замечания

- Операция может занимать значительное время при большом количестве строк и правил.
- GAS имеет лимит исполнения (6 минут). При превышении используется механизм автоматического продолжения через триггеры.
- Async-версия (`sync_full_async`) обрабатывает строки параллельно и может быть в 5-10x быстрее.
- Не запускайте полную синхронизацию, если другой процесс уже выполняется.
