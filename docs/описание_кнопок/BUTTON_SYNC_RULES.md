# 📝 Кнопка: Настройка правил синхронизации

**Файл:** `BUTTON_SYNC_RULES.md`
**Функция GAS:** `showSyncRulesManagerDialog`
**Функция сервера:** `GET /api/v1/rules/{spreadsheet_id}`, `POST /api/v1/rules/{spreadsheet_id}`
**Исполнитель логики:** `src/services/sync.py` (методы `list_rules`, `create_rule`, `update_rule`, `delete_rule`)
**Расположение в меню:** ⚙️ Настройка > 🔄 Синхронизация

---

## 📝 Описание

Открывает модальное окно для управления правилами синхронизации данных между листами. Правила определяют, какие колонки на каких листах должны автоматически синхронизироваться при изменении данных. Поддерживаются однонаправленные и двунаправленные правила.

**Ключевые особенности:**
- Визуальный интерфейс (HTML/CSS) встроенный в Google Sheets (модальное окно 1000x850 px).
- Поддержка двух режимов: `unidirectional` (один источник -> одна цель) и `bidirectional` (оба листа равноправны).
- Правила хранятся на сервере в YAML файлах (`config/rules/{spreadsheet_id}.yaml`).
- Возможность включать/выключать отдельные правила.
- Группировка правил по категориям.

---

## ⚙️ Алгоритм работы

### Фаза 1: Открытие диалога (GAS)
1. **Пользователь** нажимает кнопку "📝 Настройка правил синхронизации" в меню.
2. **GAS** получает ID текущей таблицы (`spreadsheet_id`).
3. **GAS** создает HTML-шаблон из файла `SyncRulesManager.html`.
4. **GAS** передает `spreadsheetId` в шаблон.
5. **GAS** открывает модальное окно с заголовком "Управление правилами синхронизации".

### Фаза 2: Загрузка правил (HTML -> Server)
6. **HTML-интерфейс** при загрузке отправляет `GET /api/v1/rules/{spreadsheet_id}`.
7. **Server** читает YAML-файл с правилами и возвращает список.
8. Интерфейс отображает таблицу со всеми правилами.

### Фаза 3: Редактирование (HTML)
9. Пользователь может:
   - **Создать** новое правило (задать source/target листы, заголовки, режим).
   - **Редактировать** существующее правило.
   - **Включить/выключить** правило (toggle `enabled`).
   - **Удалить** правило.
10. При сохранении интерфейс отправляет `POST /api/v1/rules/{spreadsheet_id}` с полным набором правил.

### Фаза 4: Сохранение (Server)
11. **Server** валидирует правила.
12. **Server** записывает обновленные правила в YAML-файл.
13. Кэш правил в памяти сбрасывается.

## 📋 Структура правила

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор правила |
| `enabled` | bool | Включено/выключено |
| `mode` | string | `unidirectional` или `bidirectional` |
| `category` | string | Категория (для группировки) |
| `source_sheet` | string | Лист-источник (для unidirectional) |
| `source_header` | string | Заголовок колонки источника |
| `target_sheet` | string | Лист-цель (для unidirectional) |
| `target_header` | string | Заголовок колонки цели |
| `sheet_a` / `sheet_b` | string | Листы A и B (для bidirectional) |
| `header_a` / `header_b` | string | Заголовки A и B (для bidirectional) |
| `is_external` | bool | Синхронизация с внешним документом |
| `target_doc_id` | string | ID внешнего документа (если is_external) |

## ⚠️ Важные замечания

- Изменения в правилах вступают в силу немедленно после сохранения.
- При удалении правила данные, уже синхронизированные по нему, не откатываются.
- Двунаправленные правила используют cell locking для предотвращения бесконечных циклов.
- Файл cascade_rules.yaml содержит глобальные каскадные правила (сертификация), которые применяются поверх проектных.
