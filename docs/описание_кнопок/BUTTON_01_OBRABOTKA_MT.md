# 📥 Кнопка 1: Обработка (MT / CosmeticaBar)

**Файл:** `BUTTON_01_OBRABOTKA_MT.md`
**Функция сервера:** `POST /api/v1/price/process/mt`
**Функция GAS:** `serverProcessPrimaryData` -> `callServerProcessPrice("mt", "all")`
**Исполнитель логики:** `src/services/price_processor.py` (Class `PriceProcessor`)
**Конфигурация:** `config/projects/mt.yaml`

---

## Описание

Кнопка "Обработка" запускает **полный цикл обработки прайс-листа поставщика** для проекта MT (Montibello / CosmeticaBar). Это основная операция, которая:

1. Считывает данные из внешнего документа поставщика (Б/З)
2. Парсит артикулы, цены, группы
3. Синхронизирует с листом "Главная" (присваивает ID-P, обновляет цены)
4. Заполняет ID-P на всех связанных листах
5. Копирует цены на "Динамика цены" и "Расчет цены"
6. Записывает живые формулы (EXW ALFASPA, Закупочная, DDP)
7. Реплицирует новые артикулы на все листы

**Особенность MT:** Обрабатывается в **3 последовательных цикла** (main -> tester -> samples), каждый из отдельного исходного листа.

## Алгоритм работы (15 шагов для каждого цикла)

### Фаза 1: Инициализация (GAS -> Server)

**Шаг 1.** Пользователь нажимает "📥 Обработка" в меню "Заказ".

**Шаг 2.** GAS определяет проект по ID таблицы (`CONFIG.ACTIVE_PROJECT_KEY = "MT"`).

**Шаг 3.** GAS вызывает `callServerProcessPrice("mt", "all")` -> `POST /api/v1/price/process/mt` с `mode=all`.

**Шаг 4.** Сервер запускает `process_all()` как фоновую задачу (Background Task). Пользователь получает ответ "Обработка запущена" сразу.

### Фаза 2: Чтение и парсинг данных

**Шаг 5. Загрузка конфигурации**
- Читает `config/projects/mt.yaml`
- Определяет исходный документ, листы, колонки, правила

**Шаг 6. Создание снэпшота** (аудит)
- На исходном документе создаётся копия листа с датой
- Формат: `"-Б/З поставщик 03.02.26"`
- Старые снэпшоты с таким же именем удаляются
- Некритичный шаг: если не получится — продолжаем

**Шаг 7. Чтение исходных данных**
- Открывает внешний документ `1BW8Gk5_X2EZVjbnaa2yDm-bPzzlggwQrHepeNCcPCc0`
- Читает все значения из листа (например, `-Б/З поставщик`)
- Возвращает массив строк

**Шаг 8. Парсинг данных (MT-специфичный)**

Структура исходного файла MT (колонки Excel):

| Индекс | Колонка | Содержимое |
|--------|---------|-----------|
| 0 | CODE | Артикул производителя |
| 1 | CATEGORY | Категория (для определения группы) |
| 2 | DESCRIPTION | Название ENG |
| 3 | FORMAT | Объём |
| 4 | UNITS | шт./уп. |
| 5 | PRICE | Цена EXW |
| 6 | EAN | BAR CODE |

**Логика определения групп:**
```
Если CODE заполнен AND CATEGORY пуст AND DESCRIPTION пуст:
    -> Это строка группы (CODE = название группы)
    -> current_group = CODE

Если CODE заполнен AND DESCRIPTION заполнен:
    -> Это артикул (товар)
    -> Парсим все колонки
    -> Группа = current_group + суффикс (если есть)
```

**Результат парсинга:** Массив `ParsedRow` (артикул, название, объём, штрихкод, шт/уп, цена, группа)

### Фаза 3: Очистка (только для цикла Main)

**Шаг 9. Очистка колонок** (только `mode=main`, для tester/samples пропускается)

Очищаются следующие колонки на следующих листах:

| Что очищается | Где |
|---------------|-----|
| ID-P | Главная, Сертификация, Этикетки, Заказ, Динамика цены, Расчет цены, ABC-Анализ |
| ЦЕНА EXW из Б/З | Динамика цены, Расчет цены |
| ID-G | Главная |

Очистка идет диапазоном со 2-й строки (заголовки сохраняются).

### Фаза 4: Синхронизация с листом "Главная"

**Шаг 10. Синхронизация** (`_sync_with_main`)

Это самый сложный шаг. Происходит следующее:

1. **Читает лист "Главная"** — все значения и заголовки

2. **Находит колонки по заголовкам:**

| Колонка | Поиск по | Назначение |
|---------|----------|-----------|
| ID | Точное совпадение "ID" | Идентификатор MT-001 |
| ID-P | "ID-P" | Сквозной номер (1, 2, 3...) |
| Арт. произв. | "Арт. произв" | Артикул поставщика |
| Название ENG | "Название ENG" | Название товара |
| Объём | "Объём" | Объём |
| BAR CODE | "BAR CODE" | Штрихкод |
| шт./уп. | "шт./уп" | Единицы в упаковке |
| ЦЕНА EXW | "ЦЕНА EXW" | Цена |
| Группа | "Группа" | Группа товара |

3. **Строит карту артикулов:** `{артикул: номер_строки}`

4. **Находит максимальные номера:**
   - `max_idp` = максимальный ID-P на листе (или из предыдущего цикла)
   - `max_id` = максимальный ID с префиксом MT-

5. **Загружает базу для Smart Match** (Gemini AI):
   - Берёт товары с листа "Сертификация" где "Базовый" = true
   - Кэш на 10 минут

6. **Для каждого спарсенного артикула:**

   **Если артикул НАЙДЕН на "Главная":**
   - Проверяет штрихкод (если изменился — логирует предупреждение)
   - Если ID-P пуст -> присваивает новый (max_idp + 1)
   - Если ID-P заполнен -> использует существующий
   - Обновляет цену (если price > 0)

   **Если артикул НЕ НАЙДЕН (новинка):**
   - Присваивает ID-P = max_idp + 1
   - Присваивает ID = MT-{max_id + 1} (формат MT-001)
   - Запускает **Smart Match** (Gemini AI):
     - Ищет похожий товар в базе сертификации
     - Если уверенность >= 80% — использует данные для автозаполнения
   - Создаёт новую строку на листе "Главная"
   - Добавляет в список для репликации на другие листы

7. **Применяет изменения:**
   - Batch update существующих строк
   - Append новых строк

**Шаг 11. Заполнение ID-G**
- Для строк без ID-P и без ID-G, но с группой
- Строит маппинг группа -> ID-G
- Новые группы получают последовательные номера

### Фаза 5: Распространение данных

**Шаг 12. Заполнение ID-P на всех листах**
- Строит маппинг `ID -> ID-P` с листа "Главная"
- Для каждого листа из `base_sheets_for_creation`:
  - Находит строки с ID но без ID-P
  - Заполняет ID-P из маппинга
  - Batch update по 500 ячеек
  - Пауза 2 секунды между листами

Листы для заполнения:
- Сертификация
- Этикетки
- Заказ
- Динамика цены
- Расчет цены
- ABC-Анализ

**Шаг 13. Копирование цен**
- Строит маппинг `ID-P -> цена` из спарсенных данных
- Применяет множитель цены (x1 для main/tester, x10 для samples)
- Записывает цену в колонку "ЦЕНА EXW из Б/З" на листах:
  - Динамика цены
  - Расчет цены
- Batch update по 500 ячеек

### Фаза 6: Формулы

**Шаг 14. Формулы на "Динамика цены"**

Для каждой строки (начиная с 2-й) записываются формулы в колонки текущего года:

| Колонка | Формула | Описание |
|---------|---------|----------|
| EXW ALFASPA | `=IF(B{r}<>"", B{r}*(1-C{r}), "")` | EXW * (1 - Скидка) |
| Закупочная цена | `=IF(D{r}<>"", D{r}*100, "")` | EXW ALFASPA * курс |
| DDP-МОСКВА | `=IF(E{r}<>"", E{r}*1.5, "")` | Закупочная * коэффициент |
| Прирост EXW | `=IF(AND(B{r}<>"",B{prev}<>""), (B{r}-B{prev})/B{prev}, "")` | Рост цены год к году |
| Прирост DDP | `=IF(AND(F{r}<>"",F{prev}<>""), (F{r}-F{prev})/F{prev}, "")` | Рост DDP год к году |

Формулы пишутся через `USER_ENTERED` -> Google Sheets интерпретирует их как живые формулы.

**Шаг 15. Формулы на "Расчет цены"**

INDEX/MATCH формулы для подтягивания данных из "Динамика цены":

```
=IFERROR(INDEX('Динамика цены'!$B:$B, MATCH(B{row}, 'Динамика цены'!$A:$A, 0)), "")
```

Подтягиваются: EXW текущая, EXW ALFASPA, Закупочная цена, DDP-МОСКВА.

### Фаза 7: Финализация

**Шаг 16. Репликация новых артикулов**
- Для каждого нового артикула (созданного на шаге 10)
- Создаёт строку на всех листах из `base_sheets_for_creation`:
  - Сертификация, Этикетки, Заказ, Динамика цены, Расчет цены, ABC-Анализ
- Если Smart Match нашёл совпадение — заполняет данные сертификации

**Шаг 17. Обновление статусов** (только для цикла Samples)
- На листе "Главная" для строк с ID-P, но без статуса
- Устанавливает статус "New в работу"

### Между циклами

- Пауза 15 секунд (rate limiting Google Sheets API)
- Передаётся `last_idp` для продолжения нумерации
- Если цикл упал — ошибка логируется, следующий цикл запускается

## Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Исходный лист не найден | Ошибка, цикл прерывается |
| Исходник пуст (0 данных) | Возврат `status: error`, цикл прерывается |
| Не найдены заголовки CODE/DESCRIPTION | Ошибка `ValueError` |
| Не найдена колонка ID-P на "Главная" | Ошибка `ValueError` |
| Несовпадение штрихкода | Предупреждение в логах, обработка продолжается |
| Smart Match не нашёл совпадение | Артикул создаётся без данных сертификации |
| Ошибка создания снэпшота | Предупреждение, обработка продолжается |
| Цикл tester/samples упал | Ошибка логируется, остальные циклы продолжаются |
| Превышение квоты API | Retry с exponential backoff (до 5 попыток) |
