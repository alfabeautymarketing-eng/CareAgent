# 📊 Кнопка 2: Загрузить остатки

**Файл:** `BUTTON_02_LOAD_STOCK_DATA.md`
**Функция сервера:** `POST /api/v1/stocks/load`
**Функция GAS:** `serverLoadStockData`
**Исполнитель логики:** `src/services/stock_processor.py` (Class `StockProcessor`)

---

## 📝 Описание
Эта кнопка синхронизирует данные о наличии товаров, продажах и списаниях из складского файла (или листа "-остатки") в основной лист "Заказ". Это критически важный шаг для формирования корректного заказа поставщику, так как он обновляет текущие остатки и статистику продаж.

**Ключевые особенности:**
- Работает для всех проектов (MT, SS, SK).
- Поддерживает загрузку из внешнего файла (если настроен `source_doc_id`) или локального листа.
- Обновляет не только общий остаток, но и детализацию по 3 партиям (Срок годности + Количество).
- Автоматически сопоставляет товары по Артикулу (Рус).

---

## ⚙️ Алгоритм работы (15+ шагов)

### Фаза 1: Инициализация (GAS -> Server)
1. **Пользователь** нажимает кнопку "📊 Загрузить остатки" в меню "🧾 Заказ".
2. **GAS** вызывает прокси-функцию `serverLoadStockData`.
3. **GAS** определяет ID текущей таблицы и токен авторизации.
4. **GAS** отправляет POST запрос на `/api/v1/stocks/load` с payload `{spreadsheet_id: "...", source_doc_id: null}`.
5. **Server (Router)** получает запрос в `src/api/routes/m01_zakaz.py`.
6. **Server** определяет код проекта (MT/SS/SK) по ID таблицы.

### Фаза 2: Подготовка данных (Server)
7. **StockProcessor** загружает конфигурацию проекта из `config/projects/{project}.yaml`.
8. **StockProcessor** определяет имена листов:
   - Лист назначения: обычно "Заказ" (ключ `sheets.order_form`).
   - Лист источника: обычно "-остатки" (ключ `sheets.stocks`).
9. **StockProcessor** определяет ID таблицы-источника (из конфига или текущая таблица).
10. **Server** открывает лист "Заказ" и считывает **все значения** и заголовки.
11. **Server** находит индексы целевых колонок в "Заказе":
    - Арт. Рус, Продажи, Списано, Остаток, Резерв
    - Остаток 1/2/3, СГ 1/2/3

### Фаза 3: Обработка источника (Server)
12. **Server** открывает лист-источник ("-остатки") и считывает данные.
13. **Server** определяет строку заголовков (обычно строка 3, индекс 2) и данные.
14. **Server** находит индексы колонок в источнике:
    - Артикул, Продано, Списано, Остаток, Резерв, Всего, Срок годности.
15. **Server** итерируется по строкам источника и собирает данные в `stocks_map`:
    - Ключ: Артикул (очищенный от пробелов).
    - Данные: Sales, WrittenOff, Stock, Reserve.
    - Партии: Собирает список batch'ей (кол-во + срок) для каждого артикула.

### Фаза 4: Синхронизация (Server -> Sheets)
16. **StockProcessor** итерируется по строкам листа "Заказ" (пропуская заголовок).
17. **Server** берет артикул из текущей строки "Заказа".
18. **Server** ищет данные для артикула в `stocks_map`.
19. **Если данные найдены**, подготавливает значения для обновления:
    - Заполняет `sales`, `writtenOff`, `stock`.
    - Заполняет `reserve` (если > 0).
    - Заполняет до 3-х партий (`qty1/exp1`, `qty2/exp2`, `qty3/exp3`).
20. **Server** формирует пакетный запрос (`batch_update`) для Google Sheets API.
    - Это оптимизация: один запрос вместо тысяч обновлений ячеек.
21. **Server** выполняет обновление данных в таблице.

### Фаза 5: Завершение
22. **LogService** записывает событие в лог: "Загрузка остатков завершена. Обновлено строк: X".
23. **Server** возвращает JSON ответ со статусом `success` и количеством обновленных строк.
24. **GAS** получает ответ и показывает всплывающее уведомление (Toast): "Готово! Обновлено строк: X".

---

## ✅ Критерии успеха

1. **Данные перенесены корректно:**
   - Значения в колонке "Остаток" в Заказе совпадают с "Остаток на текущий день" в источнике.
   - Значения "Продажи" и "Списано" перенесены верно.
2. **Партионный учет:**
   - Для товаров с несколькими сроками годности заполнены колонки "Остаток 1/2/3" и "СГ 1/2/3".
3. **Отсутствие ошибок:**
   - Нет ошибок `#N/A` или сдвигов строк.
   - Пустые значения в источнике не затирают формулы (если логика это предусматривает) или очищают ячейки корректно.
4. **Производительность:**
   - Операция занимает не более 30-60 секунд для таблицы в 2000 строк.

## 🧪 Тестовые сценарии

### Тест 1: Стандартная загрузка
- **Дано:** Товар Арт-001 имеет остаток 10 шт, продажи 2.
- **Действие:** Нажать "Загрузить остатки".
- **Ожидание:** В листе "Заказ" для Арт-001 появились числа 10 и 2 в соответствующих колонках.

### Тест 2: Обновление партий
- **Дано:** Товар Арт-002 имеет 2 партии: (5 шт, 2025-01-01) и (3 шт, 2026-05-01).
- **Действие:** Нажать "Загрузить остатки".
- **Ожидание:**
  - Остаток 1: 5, СГ 1: 2025-01-01
  - Остаток 2: 3, СГ 2: 2026-05-01
  - Общий остаток: 8

### Тест 3: Отсутствующий товар
- **Дано:** В листе "Заказ" есть Арт-New, которого нет в "-остатки".
- **Действие:** Нажать "Загрузить остатки".
- **Ожидание:** Поля остатков для Арт-New пустые или 0, ошибки не возникло.

### Тест 4: Изменение конфигурации (Смена источника)
- **Дано:** В `mt.yaml` изменить ID источника на тестовую таблицу.
- **Действие:** Запустить загрузку.
- **Ожидание:** Данные подтянулись из тестовой таблицы.
