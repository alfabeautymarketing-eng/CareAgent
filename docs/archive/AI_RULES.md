# Протокол Взаимодействия с ИИ (AI Interaction Protocol)

Этот документ описывает строгие правила для всех AI-агентов (Codex, Claude, Gemini, etc.), работающих над этим проектом.

## 1. Глобальные правила

- **Язык**: Все общение и комментарии к коду (где уместно для пользователя) должны быть на **Русском языке**.
- !text! **Уточняющие вопросы**: Если что-то неясно, **ВСЕГДА** задавай уточняющие вопросы. Лучше переспросить, чем сделать неправильное предположение. Не додумывай за пользователя - спрашивай!
4.  !text! **Комментарии**: В коде, предназначенном для пользователя (например, Google Apps Script), комментарии должны быть на русском языке.

## Управление задачами (Beads) - ЕДИНСТВЕННЫЙ ИСТОЧНИК ПРАВДЫ

### !КРИТИЧЕСКОЕ ПРАВИЛО!: Beads как единственный источник задач
1.  !text! **ЗАПРЕТ НА ЛОКАЛЬНЫЕ TASK.MD**: Файлы `task.md` в артефактах (например, в `.gemini/antigravity/brain/*/task.md`) используются ТОЛЬКО для временных заметок. **ЕДИНСТВЕННЫМ источником задач является Beads** (`.beads/` директория).
2.  !text! **ОБЯЗАТЕЛЬНЫЙ СТАРТ С BEADS**: Каждая сессия ИИ ДОЛЖНА начинаться с `bd ready --no-db --readonly` для просмотра готовых задач. Если команда `bd` не найдена, используйте полный путь `/Users/aleksandr/.local/bin/bd`. 
3.  !text! **СОЗДАНИЕ ЗАДАЧ**: Если Beads в режиме read-only (ошибка при `bd create`), агент ОБЯЗАН:
    - Вывести пользователю список существующих задач из `bd ready`
    - Спросить на русском: "Beads находится в режиме только для чтения. Пожалуйста, создайте задачу (`bd create`) или укажите ID существующей задачи из списка выше."
    - ДОЖДАТЬСЯ ответа пользователя с ID задачи
    - Продолжить работу ТОЛЬКО после получения ID
4.  !text! **Фокус на одной задаче**: После получения ID задачи использовать `bd pin <ID>` для назначения себе. Никогда не берись за несколько задач одновременно.
5.  !text! **Никаких анонимных правок**: ЗАПРЕЩЕНО изменять код, если нет активной задачи в `beads`. Любое изменение должно быть привязано к Issue ID.
6.  !text! **Синхронизация**: При завершении сессии выполняй `bd sync` (если есть права записи) или просто сообщи пользователю о необходимости синхронизации.

### Рабочий процесс с Beads
```bash
# 1. Проверить доступные задачи (всегда в начале сессии)
bd ready --no-db --readonly

# 2. Если Beads доступен для записи - создать задачу
bd create "Описание задачи"

# 3. Если read-only - спросить пользователя об ID задачи
# затем назначить себе:
bd pin <TASK_ID>

# 4. Работать над задачей
# ...

# 5. По завершении - синхронизировать (если есть права)
bd sync
```

### Другие обязательные правила
7.  !text! **Зависимости**: Для управления зависимостями Python используй **Poetry**. Все команды запускай через `poetry run <command>` или в `poetry shell`. Не используй `pip` напрямую без Poetry.
8.  !text! **Автосохранение**: Перед завершением каждой сессии или при достижении важных вех ОБЯЗАТЕЛЬНО запускай скрипт `bash git-autosave.sh`. Это гарантирует синхронизацию через `bd sync` и пуш изменений на GitHub.
9.  !text! **MCP Конфигурация**: Единым источником правды для всех агентов является файл `/Users/aleksandr/Library/Application Support/Claude/claude_desktop_config.json`. Любые изменения в инструментах должны вноситься туда.
10. !text! **ОБЯЗАТЕЛЬНОЕ ТЕСТИРОВАНИЕ**: Все логические изменения ДОЛЖНЫ быть протестированы агентом через скрипты или API-вызовы перед завершением задачи. Агент должен предоставить доказательства успешного тестирования (логи, результаты выполнения команд).
11. **Проверка портов**: Перед завершением любого ответа или задачи, ИИ-агент обязан проверить работоспособность всех портов проекта (например, через `/health`). В ответе должна быть предоставлена ссылка на файл, где определены данные порты.
12. **Контекст**: Агент должен всегда учитывать структуру проекта (GAS + Python Server) и стремиться к переносу логики на сервер.

## 2. Синтаксические Маркеры

### `!текст!` (Восклицательные знаки)
Если пользователь заключает текст в восклицательные знаки (например, `!сохрани эту структуру!`), это является **КРИТИЧЕСКИМ ТРЕБОВАНИЕМ**.
- **Действие**: Это правило/требование становится "священным". Агент обязан зафиксировать его в своей памяти или в файле правил (например, здесь или в `task.md`) и **никогда** не нарушать.
- **Приоритет**: Наивысший. Перекрывает любые "лучшие практики", если они противоречат этому правилу.

## 3. Архитектурные Принципы

1.  **Server-First**: Вся бизнес-логика должна выполняться на Python-сервере.
2.  **GAS как Мост**: Google Apps Script должен выполнять только роль "Тонкого Клиента" (Thin Client):
    - Сбор данных (событие onEdit, значения ячеек).
    - Отправка запроса на сервер.
    - Примененение ответа (запись в ячейки).
    - **запрещено** писать сложную логику обработки данных в GAS.
3.  **Синхронизация**: Приоритет №1. Данные должны быть согласованы. Если есть правило, оно должно сработать (даже при вставке Copy-Paste огромного массива).
4.  **Комментарии миграции**: При переносе функции из GAS в Python, старый код в GAS **обязательно** должен быть закомментирован (не удален сразу), чтобы сохранить историю и возможность отката, с пометкой `// MIGRATED TO SERVER`.
5.  **!Деплой во все проекты (Атомарность)!**: При любых изменениях в Google Apps Script код ДОЛЖЕН быть задеплоен во **ВСЕ проекты** (MT, SS, SK) одновременно через `bash scripts/push_all_gas.sh`.
    - **Атомарность**: Изменение кода без деплоя во все связанные проекты считается незавершенной работой и грубой ошибкой. Задача не может быть закрыта, пока системы рассинхронизированы.
    - **Перспектива**: В будущем следует рассмотреть переход на использование Библиотек Google Apps Script для автоматической синхронизации изменений во всех проектах.
6.  !text! **Серверные логи**: Детальные логи выполнения каждой функции (сервер или GAS) должны храниться на сервере. Каждый шаг алгоритма логируется структурировано: функция, шаг, статус, длительность, краткий контекст/итог.
7.  !text! **Покрытие логами**: Агент обязан пройти все действующие функции и добавить шаги логирования согласно фактическому алгоритму (сервер/скрипт), затем структурировать события.
8.  !text! **Журнал синхро**: Хранить "Журнал синхро" на сервере (без листа в таблице) и предоставлять доступ через UI.
9.  !text! **Использование ИИ для оптимизации**: Агент имеет право в любой момент подключать возможности ИИ (в т.ч. через Gemini API) для сложных расчетов, обработки или глубокой аналитики данных внутри проек та, если это оптимизирует процесс. Для ресурсоемких задач следует использовать прямое подключение к Gemini по API через CLI/терминал, где доступен полный ресурс и гибкость настройки, с последующей интеграцией результатов в архитектуру сервера.
