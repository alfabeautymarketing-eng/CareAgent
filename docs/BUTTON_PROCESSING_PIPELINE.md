# 📋 Рабочий процесс для документирования и тестирования кнопок AgentCare

**Версия:** 1.0
**Автор:** AI Agent
**Дата создания:** 2026-01-22
**Статус:** В разработке

---

## 🎯 Общий подход

Каждая кнопка должна пройти следующий цикл работы:

### 1️⃣ **Документирование функционала**
Полное описание структуры, правил выполнения, последовательности функций и результата

### 2️⃣ **Нажатие кнопки (тестирование)**
Фактический запуск функции через нажатие кнопки в Google Sheets

### 3️⃣ **Анализ логов**
Проверка логов на сервере (Supabase + журналы выполнения) для всех функций, связанных с кнопкой

### 4️⃣ **Подтверждение и согласование**
Подтверждение агентом и пользователем что все функции выполняются корректно

### 5️⃣ **Переход к следующей кнопке**
При переходе проверить не изменилась ли структура кнопок, при необходимости обновить план

---

## 📌 Правила переходов между кнопками

- ✅ **ПЕРЕД** переходом к новой кнопке всегда проверить:
  - Изменилась ли структура кнопок в меню
  - Добавились ли новые кнопки
  - Переименовались ли существующие кнопки
  - Изменились ли зависимости между кнопками

- ✅ **ЕСЛИ** есть изменения в структуре:
  - Обновить документ с описанием новой структуры
  - Скорректировать план работ
  - Переобсудить с пользователем

## 🔄 Жизненный цикл продукта в AgentCare

Система разделена на **4 главных этапа**:

### **Этап 1: 🏷️ Прайс-лист**
- Получение листов от производителя
- Обновление актуальных данных
- Загрузка остатков

### **Этап 2: 🛒 Заказ & Документация**
- Подготовка к продаже
- Таможня и сертификация
- Создание документов

### **Этап 3: 📦 Экспорт & Выгрузка**
- Форматирование финальных листов
- Создание инвойса
- Сбор документов

### **Этап 4: 🤖 AI Агент**
- Дополнительная аналитика
- Классификация товаров
- Поиск ТН ВЭД кодов

## 📊 Логирование и отладка

### Где смотреть логи:

1. **Серверные логи** (Python/FastAPI):
   - Стандартный вывод сервера
   - Логи в консоли (если запущено локально)

2. **Логи в Supabase**:
   - Таблица: `sync_logs` (логи синхронизации)
   - Таблица: `function_logs` (логи функций)
   - Таблица: `events` (события)

3. **UI Журнал** (веб-интерфейс):
   - Открывается по кнопке "📜 Открыть Журнал (UI)" в меню "🟢 Ecosystem"
   - Содержит фильтры, сортировку, поиск, временной диапазон

### Что логируется для каждой функции:

```
├─ Начало выполнения функции
│  ├─ Входные параметры
│  ├─ Версия функции
│  └─ Временная метка
│
├─ Этапы выполнения (шаг за шагом)
│  ├─ Шаг 1: [Описание]
│  ├─ Шаг 2: [Описание]
│  └─ ...
│
├─ Результаты
│  ├─ Статус (успешно/ошибка)
│  ├─ Обработано записей/данных
│  └─ Выходные параметры
│
└─ Завершение
   ├─ Длительность выполнения
   ├─ Потребленные ресурсы
   └─ Статус синхронизации с БД
```

## 🔗 Структура документов кнопок

Для каждой кнопки будет создан отдельный документ в `docs/BUTTONS/` с расширением `.md`:

### Имя файла: `BUTTON_[STAGE]_[NAME].md`

**Пример:**
- `BUTTON_STAGE1_PROCESS_PRIMARY_DATA.md` - Обработка первичной документации

### Содержание документа:

```
# [Название кнопки]

## 📍 Положение в меню
- Этап: [номер]
- Подменю: [название]
- Порядок: [номер по порядку]

## 📝 Описание функции
[Что делает эта кнопка]

## 🔄 Функциональные этапы
[Подробное описание каждого этапа]

## 📋 Входные данные
[Какие данные нужны на вход]

## 📤 Выходные данные
[Какие результаты должны быть]

## 🔗 Зависимости
[От каких функций зависит]
[Какие функции зависят от этой]

## 📊 Логирование
[Какие логи проверять]
[Критические точки]

## ✅ Критерии успешного выполнения
[Что считается успехом]

## 🐛 Частые ошибки
[Известные проблемы]
[Как их решать]

## 🧪 Тестовые сценарии
[Сценарий 1]
[Сценарий 2]
...

## 📌 Особенности по проектам
- **MT**: [Отличия]
- **SS**: [Отличия]
- **SK**: [Отличия]
```

## 📌 Примечания

- Каждая кнопка работает с одной основной функцией на сервере
- Кнопка может вызывать несколько вспомогательных функций
- Все функции должны быть задокументированы в коде (docstrings)
- Логирование должно быть **максимально детальным**
- При обнаружении ошибок - сначала проверить логи, потом исправлять код
