# Кнопки «Логи»: текущее поведение

Порядок соответствует группе "📋 Логи" в `src/api/endpoints.py`.

## Карта по листам
### Лист "Логи" (SESSION_LOG)
- 📊 Статус архивирования — читает статус архивации (учитывает "Логи", "Журнал синхро", "Журнал логов"), ничего не изменяет.
- 📁 Архивировать логи сейчас — архивирует все три листа и очищает именно "Логи".
- ⏰ Установить триггер (полночь) — настраивает ежедневное архивирование + очистку "Логи".
- 🗑️ Удалить триггер — отменяет ежедневное архивирование (косвенно влияет на "Логи").

### Лист "Журнал синхро"
- 📝 Пересоздать Журнал синхро — удаляет лист и создаёт заново с шапкой.
- 🧹 Очистить Журнал синхро — удаляет старые строки, оставляет 100 последних.

### Примечание
- Архивация всегда затрагивает ещё и "Журнал логов" (DEBUG), хотя отдельной кнопки для него в меню нет.

## 1) 📊 Статус архивирования
- Обработчик: `showArchiveStatus_proxy` → `Lib.showArchiveStatus` (оба в `gas/09LogArchive.gs`).
- Что происходит по шагам:
  1) Берётся UI через `SpreadsheetApp.getUi()`.
  2) Из `PropertiesService.getScriptProperties()` читается дата последнего архивирования по ключу `ECOSYS_LAST_LOG_ARCHIVE_DATE` (если пусто — выводится "Никогда").
  3) Определяется код проекта через `_getProjectCode_()`:
     - сначала пытается взять `project` из `getMenuConfig({ skipFetch: true })`;
     - если недоступно — анализирует имя таблицы (mt/mettler, sk/skinakas, ss/skinscience);
     - иначе использует `project` как fallback.
  4) Формируется имя текущего архива: `<projectCode>-<месяц>-<год>` (месяц берётся из `LOG_ARCHIVE_CONFIG.MONTHS_RU`).
  5) Проверяется наличие триггера `midnightLogRotation_trigger` через `ScriptApp.getProjectTriggers()`.
  6) Формируется текст статуса и показывается `ui.alert` со строками:
     - "Последнее архивирование";
     - "Текущий архив";
     - "Автоматический триггер" (установлен/не установлен);
     - "Папка архивов" (ID из `LOG_ARCHIVE_CONFIG.ARCHIVE_FOLDER_ID`).
- Изменений данных не делает — только читает состояние и показывает окно.

## 2) 📁 Архивировать логи сейчас
- Обработчик: `manualArchiveLogs_proxy` → `Lib.manualArchiveLogs` (оба в `gas/09LogArchive.gs`).
- Что происходит по шагам:
  1) Открывается подтверждение `ui.alert` (YES/NO). Без подтверждения функция завершается.
  2) Показывается toast "⏳ Архивирование..." на 30 секунд.
  3) Запускается `Lib.midnightLogRotation()`.
     - Внутри сначала `_shouldArchiveToday_()` сравнивает последнюю дату архивирования (`ECOSYS_LAST_LOG_ARCHIVE_DATE`) с сегодняшней датой (Europe/Moscow). Если уже архивировали сегодня — возвращается `skipped`.
     - Если архивирование нужно, вызывается `Lib.archiveLogsDaily()`:
       - Получает активную таблицу.
       - Открывает/создаёт месячную архивную таблицу через `_getOrCreateMonthlyArchiveSheet_(now)`:
         - Имя архива: `<projectCode>-<месяц>-<год>`.
         - Пытается взять ID архива из `ECOSYS_MONTHLY_ARCHIVE_SHEET_ID_<year>_<month>`.
         - Если нет — ищет файл по имени в папке `LOG_ARCHIVE_CONFIG.ARCHIVE_FOLDER_ID`.
         - Если не найден — создаёт новую таблицу, переносит в папку архивов, сохраняет ID, инициализирует листы под лог‑типы.
       - Для каждого листа из `LOG_ARCHIVE_CONFIG.SHEETS_TO_ARCHIVE` ("Логи", "Журнал синхро", "Журнал логов"):
         - Берёт все строки без заголовка.
         - Добавляет колонку "📅 Дата архивации" (текущее время).
         - Дописывает строки в соответствующий лист архива (создаёт его при отсутствии).
       - Обновляет `ECOSYS_LAST_LOG_ARCHIVE_DATE` на сегодняшнюю дату.
     - После успешного архивирования выполняется `Lib.resetDailyLogSheet()`:
       - Очищает лист "Логи" (удаляет все строки кроме заголовка) или создаёт его с базовой шапкой, если лист отсутствует.
       - ВАЖНО: очищается именно "Логи" (SESSION_LOG), а не "Журнал синхро".
  4) По результату показывается `ui.alert`:
     - если `skipped`: "Логи уже были архивированы сегодня";
     - если успех: количество скопированных записей и имя архива;
     - если ошибка: показывается текст ошибки.

## 3) ⏰ Установить триггер (полночь)
- Обработчик: `setupMidnightLogTrigger_proxy` → `Lib.setupMidnightLogTrigger` (оба в `gas/09LogArchive.gs`).
- Что происходит по шагам:
  1) Удаляются все существующие триггеры с обработчиком `midnightLogRotation_trigger`.
  2) Создаётся новый time‑based триггер:
     - функция `midnightLogRotation_trigger`;
     - запуск каждый день в 00:00;
     - таймзона `Europe/Moscow`.
  3) Показывается `ui.alert` о том, что архивирование будет выполняться каждый день в полночь и складываться в архивную папку.

## 4) 🗑️ Удалить триггер
- Обработчик: `removeMidnightLogTrigger_proxy` → `Lib.removeMidnightLogTrigger` (оба в `gas/09LogArchive.gs`).
- Что происходит по шагам:
  1) Ищутся триггеры с обработчиком `midnightLogRotation_trigger`.
  2) Каждый найденный триггер удаляется, ведётся счётчик удалённых.
  3) Показывается `ui.alert` с количеством удалённых триггеров.

## 5) 📝 Пересоздать Журнал синхро
- Обработчик: `recreateLogSheet` → `Lib.recreateLogSheet` (оба в `gas/03Синхронизация.js`, прокси в `gas/00_GlobalApiBridge.js`).
- Что происходит по шагам:
  1) Запрос подтверждения удаления всех данных (YES/NO). Без подтверждения — выход.
  2) Определяется имя листа через `Lib.CONFIG.SHEETS.LOG` (см. `gas/01Config.js`, значение по умолчанию "Журнал синхро").
  3) Если лист существует — удаляется целиком.
  4) Создаётся новый лист и вызывается `_initLogSheetStructure_(sh)`:
     - удаляет все правила валидации данных и защищённые диапазоны;
     - устанавливает шапку `Lib.__LOG_HEADERS__` в точном порядке:
       "Дата/время", "ID", "Источник", "Цель", "Старое значение", "Новое значение", "Категория", "Хэштеги", "Событие";
     - включает bold и wrap для шапки, фиксирует 1‑ю строку;
     - выставляет формат даты для 1‑го столбца;
     - задаёт ширины колонок (1–4) для удобства чтения.
  5) Показывается `ui.alert` об успехе, пишется debug‑лог; при ошибке — `ui.alert` с ошибкой и запись в лог.
- ВАЖНО: действие полностью удаляет ВСЕ записи "Журнала синхро".

## 6) 🧹 Очистить Журнал синхро
- Обработчик: `quickCleanLogSheet` → `Lib.quickCleanLogSheet` (оба в `gas/03Синхронизация.js`, прокси в `gas/00_GlobalApiBridge.js`).
- Что происходит по шагам:
  1) `_getOrCreateLogSheet_()` открывает лист `Lib.CONFIG.SHEETS.LOG` и, если нужно, создаёт или чинит его структуру (через `_initLogSheetStructure_`).
  2) Считается количество записей (строки без заголовка).
  3) Если записей ≤ 100 — выводится `ui.alert`, что очистка не требуется.
  4) Если записей > 100 — запрашивается подтверждение:
     - удаляются самые старые строки (строки 2..N‑100);
     - остаются последние 100 записей;
     - показывается `ui.alert` с итогом и пишется инфо‑лог.
  5) При ошибке — `ui.alert` с текстом ошибки и запись в лог.
