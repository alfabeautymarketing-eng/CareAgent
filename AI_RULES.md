# Протокол Взаимодействия с ИИ (AI Interaction Protocol)

Этот документ описывает строгие правила для всех AI-агентов (Codex, Claude, Gemini, etc.), работающих над этим проектом.

## 1. Глобальные правила

- **Язык**: Все общение и комментарии к коду (где уместно для пользователя) должны быть на **Русском языке**.
4.  !text! **Комментарии**: В коде, предназначенном для пользователя (например, Google Apps Script), комментарии должны быть на русском языке.

## Управление задачами (Beads)
1.  !text! **ОБЯЗАТЕЛЬНЫЙ СТАРТ**: Каждая сессия ИИ и каждая новая задача (даже мелкая!) ДОЛЖНА начинаться с проверки задач (`bd ready`) или создания новой (`bd create`).
2.  !text! **Фокус на одной задаче**: Использовать `bd pin` для назначения задачи себе. Никогда не берись за несколько задач одновременно. Выполняй одну, отмечай как `closed`, только потом переходи к следующей.
3.  !text! **Никаких анонимных правок**: ЗАПРЕЩЕНО изменять код, если нет активной задачи в `beads`. Любое, даже самое мелкое изменение кода, должно быть привязано к Issue ID.
4.  !text! **Синхронизация**: При завершении сессии или перед коммитом всегда выполняй `bd sync`.
5.  !text! **Зависимости**: Для управления зависимостями Python используй **Poetry**. Все команды запускай через `poetry run <command>` или в `poetry shell`. Не используй `pip` напрямую без Poetry.
6.  !text! **Автосохранение**: Перед завершением каждой сессии или при достижении важных вех ОБЯЗАТЕЛЬНО запускай скрипт `bash git-autosave.sh`. Это гарантирует синхронизацию через `bd sync` и пуш изменений на GitHub.
7.  !text! **MCP Конфигурация**: Единым источником правды для всех агентов является файл `/Users/aleksandr/Library/Application Support/Claude/claude_desktop_config.json`. Любые изменения в инструментах должны вноситься туда.
8.  !text! **ОБЯЗАТЕЛЬНОЕ ТЕСТИРОВАНИЕ**: Все логические изменения ДОЛЖНЫ быть протестированы агентом через скрипты или API-вызовы перед завершением задачи. Агент должен предоставить доказательства успешного тестирования (логи, результаты выполнения команд).
- **Контекст**: Агент должен всегда учитывать структуру проекта (GAS + Python Server) и стремиться к переносу логики на сервер.

## 2. Синтаксические Маркеры

### `!текст!` (Восклицательные знаки)
Если пользователь заключает текст в восклицательные знаки (например, `!сохрани эту структуру!`), это является **КРИТИЧЕСКИМ ТРЕБОВАНИЕМ**.
- **Действие**: Это правило/требование становится "священным". Агент обязан зафиксировать его в своей памяти или в файле правил (например, здесь или в `task.md`) и **никогда** не нарушать.
- **Приоритет**: Наивысший. Перекрывает любые "лучшие практики", если они противоречат этому правилу.

## 3. Архитектурные Принципы

1.  **Server-First**: Вся бизнес-логика должна выполняться на Python-сервере.
2.  **GAS как Мост**: Google Apps Script должен выполнять только роль "Тонкого Клиента" (Thin Client):
    - Сбор данных (событие onEdit, значения ячеек).
    - Отправка запроса на сервер.
    - Примененение ответа (запись в ячейки).
    - **запрещено** писать сложную логику обработки данных в GAS.
3.  **Синхронизация**: Приоритет №1. Данные должны быть согласованы. Если есть правило, оно должно сработать (даже при вставке Copy-Paste огромного массива).
4.  **Комментарии миграции**: При переносе функции из GAS в Python, старый код в GAS **обязательно** должен быть закомментирован (не удален сразу), чтобы сохранить историю и возможность отката, с пометкой `// MIGRATED TO SERVER`.

## 4. База Знаний (Cross-Agent Memory)

- Если агент находит противоречие в коде или правилах, он должен спросить пользователя.
- Если вводится новое "правило навсегда", оно должно быть добавлено в этот файл (`AI_RULES.md`).
